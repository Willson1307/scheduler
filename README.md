# 课表活动撞车难调，AI求解一键消解

> 仓库名：`scheduler`（刻意不叫 school-scheduler：模型不绑定学校场景，
> 组织树、节次、资源全部可配置，后续可推广到培训机构排课、企业培训与会议室排期）

中学的课表（长期重复事务）和活动（一次性事务）通常各管各的：排课时看不见已安排的活动，
于是撞车；出了冲突又只能靠人反复试。本项目把两者归一化到同一套底层模型——
「某个对象在某天的哪些节次被占用」——用位运算做统一的冲突检测，再让自建的约束求解器
做自动排布与一键消解：硬约束（教师、教室、班级撞课，教室容量）保证百分之百满足；
软约束（连堂、单日课时上限、主科不排末节等）以代价形式参与权衡，其权重由本校公开的
往期课表统计学习得到（w = −ln(1−p)，p 为历史满足率）。

权限上，「可被调度的对象」与「可登录的账号」是正交的两层：谁能在哪个组里看什么、改什么，
由沿组织树继承的四档授权（查看/编辑/管理/拥有）决定；学生一定在对象图里，但不一定需要账号。

自然语言入口采用五层降级架构：本地规则解析器（覆盖 70–80%，零 API、断网可用）是绝对主力，
云端大模型仅在本地层无法解析时作为可选增强，且失败会自动静默回落。
**全部计算在本地完成，断网也能运行。**

## 五条最重要的设计约定

1. **对象 ≠ 账号。** `objects` 里可以有 1500 个学生行（用于调度与冲突检测），
   `users` 里只放真正需要登录的人。学生不持有终端，就不必发密码。
2. **位图是加速层，不是真相层。** 真相是 `period_slots` 配置 + 周期规则 + 起止时刻；
   位图只在检测时展开出来，让冲突判断变成一次按位与。
3. **课表与活动共享底层。** 两者都归一化为「(日期, 当天槽位掩码)」，
   冲突检测只有一套位运算。这样排课才看得见已安排的活动，不会撞车。
4. **权限按组、四档、沿闭包继承。** 查看 → 编辑（改自己参与的）→ 管理（改本组任何人的）→ 拥有（含授权他人）；
   多条路径取最高档；全局角色是天花板；**刻意不做负权限**（多父结构下语义不自洽）。
5. **AI 只负责"听懂"，不负责"算"。** 求解与结果解释全在本地；
   外部模型只在自然语言入口做可选增强，且失败静默回落，断网不受影响。

更多说明见 [`docs/00-架构速览.md`](docs/00-架构速览.md)。

## 已知限制（诚实列出）

- 暂不支持调课补课（数据模型已定义，功能未实现）。
- 跨天活动需拆成两条一次性日程，且必须属于同一组。
- 非整节（如 14:15–15:00）的安排支持有限，按连续区间处理。

## 注意事项

- 数据库文件（`data/*.db`）**不入库**：里面会有真实的学生名单与课表，按学校规定不得外传。
- 演示与现场必须使用**断网也能跑**的本地 SQLite，不依赖任何外部 API。
- 发给外部大模型的内容**只能是用户指令文本**，严禁携带课表、班级名、姓名、联系方式。
