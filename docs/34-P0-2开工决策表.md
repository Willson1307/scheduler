## 🔴 阻塞项 ③：`as_of_dow` 的三个语义待定

`docs/12` 已给 `as_of_dow INTEGER`（1-7），但有三个问题文档没答：

### Q1 · NULL 时怎么办？🔴 **这是最关键的**

| 选项 | 行为 | 风险 |
|---|---|---|
| **①抛异常**（我建议） | 调休日忘填 `as_of_dow` → 报错 | 无 |
| ② 静默按自然周几 | 回到今天的 bug | 🔴 **等于没修**，且是典型的「静默失效」 |
| ③ 计数并上报 | 跳过该日 + 记录 `skipped` | 可接受，但 `scan()` 会漏报该日冲突 |

> **P0-3 的核心教训就是「宁可报错也不要静默跳过」**——
> 假阴性（系统说没冲突、实际有）比报错危险得多。
> 漏报冲突直接毁掉本系统的全部价值主张。

### Q2 · 存 `1..7` 还是 `'mon'..'sun'`？

| 方案 | 优点 | 缺点 |
|---|---|---|
| **`1..7`**（我建议） | 与 `period_slots.day_of_week` **同口径**，省一次转换 | 无 |
| `'mon'..'sun'` | 人读友好 | 每次查询要映射，多一个出错点 |

### Q3 · 生效范围

`kind='makeup'` 且 `as_of_dow` 有值时才读它；`holiday` 及其他情况忽略 —— **这条我建议直接定，没有争议**。
