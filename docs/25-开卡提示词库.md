## 🆕 通用验收项：凡 PR 改 `schema.sql` 新增表（2026-10-11 立）

> **来源**：PR#5（B5 /api/demands）审查实测踩中，**同款陷阱已踩两次**
> —— `event_log` 表一次、`demands` 表一次。

### 坑在哪

`config.py`的 `ensure_database` **只在库文件不存在时 seed**。已存在的
`data/*.db`（`trial.db` / `demo.db`）**永远不会补进 `schema.sql` 新增的表**。

后果：

```
缺表时 POST → HTTP 500 {"error":"internal server error"}
同时       → /api/health 仍报 200     ← 假绿灯
doctor.py  → 14/14 通过             ← 假绿灯
契约测试    → 用新建库，全绿          ← 假绿灯
```

**三道门全过，接口实际是坏的。**

### 强制验收动作

PR 里只要出现 `schema.sql` 新增 `CREATE TABLE`，**必须在缺表旧库上真打一次接口**：

```bash
# 1. 看这个 PR 新增了哪些表
git diff main -- src/scheduler/schema.sql | grep "^+.*CREATE TABLE"

# 2. 造缺表旧库（<新表名> 替换成上面查到的表名）
cp data/demo.db data/oldlib.db
python -c "import sqlite3;c=sqlite3.connect('data/oldlib.db');c.execute('DROP TABLE IF EXISTS <新表名>');c.commit()"

# 3. 指向它启动
python scripts/run_server.py --port 8000 --today 2026-10-12 --db data/oldlib.db

# 4. 真打一次写接口，看是不是 200
```

⚠️ **不要对 schema 里全部 14 张表逐一要求 `ensure_*`** —— 那是误报。
`ensure_database` 只在库不存在时 seed，基础表在新库里必然存在。
**本项只管「本 PR 新增的表」**，判据是diff，不是 schema 全量。

**修法范式**（照 `telemetry.ensure_event_log`）：

```python
def ensure_<table>(conn: sqlite3.Connection) -> None:
    """确保 <table> 表存在（幂等）。

    🔴 已存在的 data/*.db 不会补进 schema.sql 新增的表
    （ensure_database 只在库文件不存在时 seed）→ 缺表时接口 500，
    而 /api/health 仍报 200 → 假绿灯。
    **schema.sql 是唯一 DDL 来源**，杜绝表结构两处各写一遍的漂移。
    """
    row = conn.execute(
        "SELECT 1 FROM sqlite_master WHERE type = 'table' AND name = '<table>'"
    ).fetchone()
    if row is None:
        init_db(conn)
```

调用点在写之前：`conn = config.open_db()` 之后立刻 `ensure_<table>(conn)`。
