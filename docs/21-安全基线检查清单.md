## 1. 🔴 B2 鉴权代码人工复核（降档专项，交付当场逐条核）

> **为什么这节必须人工逐条核**：B2 权限层的鉴权代码由 **GLM-5.2 生成**
> （GLM-5.3 因平台封禁不可用，同族小版本降档，已获队长批准——理由：同族 5.2→5.3 属代内
> 版本差距，语义一致性优于跨族 V4-Pro）。**降档的原始风险点 = 生成代码的鉴权语义可能带偏**
> → 这 5 项缺一不可，任何一项拿不出证据即判「B2 未通过」。

### 1.1 越权路径（IDOR）—— 非 admin 能否改 URL 参数访问他人数据

- [ ] **B2-1 · 越权访问被拦截**
  - 检查命令：
    ```bash
    python -m unittest tests.test_server_api -v          # 看越权用例是否真实跑且断言 403/404
    grep -n "org_id" src/server/api_*.py                # 每个 handler 是否都带 org_id 过滤
    ```
  - 判定标准：
    - **通过** = 用「低档账号」改 URL 里的 `object_id` / `schedule_id` / `group_id` 访问他人组织数据，一律返回 **403 或 404**，响应体**不含任何他人数据字段**；
    - **不通过** = 任一接口能用他人 id 读到 / 改到 / 删到数据，或只在前端隐藏、后端不拦。
  - 覆盖缺陷：**P2-1**（`schedules.py:110,150` 两接口无 org 过滤，典型 IDOR）。

### 1.2 缺省组判定 —— 是否用 `parent_name is None` 而非 `min(level)`

- [ ] **B2-2 · 缺省组判据正确**
  - 检查命令：
    ```bash
    grep -n "parent_name\|MIN(level)\|min(level)" src/scheduler/authz.py
    ```
  - 判定标准：
    - **通过** = 源码里缺省组判定用 `parent_name IS NULL` / `parent_name is None`（根组无父节点）；
    - **不通过** = 出现 `MIN(level)` / `min(level)` 当缺省组判据（层级深度在 `object_edges.depth`，**不在** `group_roles.level`，用 min(level) 会判错）。

### 1.3 多路径继承 —— 同一对象经多条祖先链时是否取最高档

- [ ] **B2-3 · 多路径取最高档**
  - 检查命令：
    ```bash
    grep -n "MAX(level)\|max(" src/scheduler/authz.py
    python -m unittest tests.test_authz -v               # 必须含多父 DAG 用例
    ```
  - 判定标准：
    - **通过** = 继承取 **MAX(level)**，且测试覆盖「同一对象经多条祖先链」场景（如成员同时属班级与社团，`groups_of` 多条、祖先深度 `{2,1,1}` 类场景），最终档位 = 各路径最高档；
    - **不通过** = 只取第一条路径、或取 min、或没有多父用例。

### 1.4 `password_hash` 是否绝不出现在 `/api/login` 响应体里

- [ ] **B2-4 · 口令哈希零回传**
  - 检查命令：
    ```bash
    grep -n "password_hash" src/server/*.py            # 确认 login handler 已 pop 掉该字段
    # 实测：登录成功后打印/检查 JSON 响应体，字段列表里不得出现 password_hash
    ```
  - 判定标准：
    - **通过** = `/api/login` 成功 / 失败响应体里**均无** `password_hash` 字段（`authenticate` 返回值已 `pop("password_hash")` 或改用专用结构）；
    - **不通过** = 响应或会话里出现该字段（覆盖缺陷：**P2-2**，`object_graph.py:295`）。

### 1.5 commit message 是否写明「由 GLM-5.2 生成」及降档原因

- [ ] **B2-5 · 降档溯源可答**
  - 检查命令：
    ```bash
    git log --oneline -20 | grep -i "B2\|authz\|鉴权\|GLM"
    ```
  - 判定标准：
    - **通过** = B2 鉴权相关 commit 的 message 里**写明了「由 GLM-5.2 生成」+ 降档原因**（GLM-5.3 平台封禁、同族代内降档、队长已批准）；
    - **不通过** = commit 里无任何溯源说明 → 评委问「这段谁写的」时答不清，判 B2 未通过。

> 📌 §1 结论栏（交付时填）：`B2-1 __ B2-2 __ B2-3 __ B2-4 __ B2-5 __`　全部通过才放行。

## 2. 硬性红线（照 AGENTS.md / 项目指令，违反即返工，无需权衡）

- [ ] **R1 · 零第三方依赖**
  - 检查命令：
    ```bash
    cat requirements.txt                                   # 应全为注释/占位
    grep -rnE "^\s*(import|from)\s+" src/ scripts/ --include=*.py
    ```
  - 判定标准：`requirements.txt` 全注释；所有 `import` / `from` 仅命中 **Python 标准库**（`sqlite3` / `hashlib` / `hmac` / `http.server` / `json` / `secrets` 等）。出现任何 `requests` / `flask` / `fastapi` / 第三方包名 = 不通过。

- [ ] **R2 · 断网可跑**
  - 检查命令：
    ```bash
    python scripts/smoke.py --offline
    ```
  - 判定标准：断网（拔网 / 禁用外联）后重跑仍 **全 PASS**，无任何对外请求。这是赛事章程硬要求。

- [ ] **R3 · 前端代码不得出现密钥**
  - 检查命令：
    ```bash
    grep -rnE "api_key|secret|password|token|sk-" web/ --include=*.js --include=*.html
    ```
  - 判定标准：`web/` 下**零命中**任何密钥 / 口令 / 令牌字面量（前端不持有任何凭证）。

- [ ] **R4 · `/api/login` 响应绝不回传 `password_hash`**
  - 同 §1.4（B2-4），红线级重复强调。判定标准一致：响应体无该字段。

- [ ] **R5 · `schema.sql` 只能末尾追加，不动已有表**
  - 检查命令：
    ```bash
    git diff feat/server-authz...main -- src/scheduler/schema.sql   # 或直接 diff 审查
    ```
  - 判定标准：B2 对 `schema.sql` 的改动**仅限末尾追加 `group_roles` 建表语句**，已有表（`objects` / `users` / `schedules` …）结构一行未动。

- [ ] **R6 · `group_roles` 列名必须是 `level`**
  - 检查命令：
    ```bash
    grep -n "CREATE TABLE.*group_roles" -A 20 src/scheduler/schema.sql
    ```
  - 判定标准：`group_roles` 表存在，且权限档位列名 = `level`（**不是** `grant` —— `GRANT` 是 SQL 保留字）。

## 3. 上公网前必查项（CP-H，10/7 24:00 前逐条勾）

> 这部分覆盖「一旦暴露公网」才放大的风险面。**内网试用可不全勾，但上公网前必须全绿。**

- [ ] **H1 · 组织隔离（越权 403/404 全覆盖）**
  - 检查命令：`python -m unittest tests.test_server_api -v`
  - 判定标准：越权用例全绿；`edit` 档看不到他人日程（覆盖 docs/19 CP-C）。

- [ ] **H2 · 登录失败限流 / 锁定**
  - 检查命令：
    ```bash
    grep -n "attempt\|fail\|lock\|throttle\|退避\|限流" src/server/*.py
    ```
  - 判定标准：
    - **上公网** = 存在登录失败计数 + 退避 / 锁定逻辑（覆盖缺陷：**P2-3**，无此则公网可爆破）；
    - **仅内网演示** = 至少登录失败有日志（临时可接受，但须在材料里如实标注「未上公网」）。

- [ ] **H3 · 会话 / 令牌机制安全**
  - 检查命令：`grep -n "Set-Cookie\|HttpOnly\|SameSite\|session" src/server/*.py`
  - 判定标准：会话 cookie 带 **HttpOnly + SameSite**；有服务端会话表；登出即失效（覆盖 docs/16 **S5**）。无令牌机制或 cookie 可被 JS 读取 = 不通过。

- [ ] **H4 · 口令哈希强度**
  - 检查命令：`grep -n "pbkdf2\|iterations\|rounds" src/scheduler/*.py`
  - 判定标准：
    - 上公网 = rounds **≥ 300k** 且单次登录耗时 < 1s（实测）；
    - 演示环境 = ≥ 100k 可接受（docs/16 **S4**：当前 100k，低于 OWASP 建议 600k，演示可用、上公网需提）。
  - 阈值来源：docs/16 §4 S4。

- [ ] **H5 · SQL 注入防护**
  - 检查命令：`grep -n "execute(" src/ --include=*.py | grep -v "%"`（抽查是否有 f-string 拼接值）
  - 判定标准：所有 SQL 值**参数化**（占位符 `?`），无 `f"...{var}..."` 直接拼值。docs/16 §4 已确认「全部 SQL 参数化，无 SQL 注入」——本项为回归确认，别让后续改动引入。

- [ ] **H6 · 时序攻击防护**
  - 检查命令：`grep -n "compare_digest" src/scheduler/*.py`
  - 判定标准：口令校验用 `hmac.compare_digest`（常量时间比较），不得用 `==` 比较哈希。

- [ ] **H7 · 真实数据不出校、不上公网**
  - 检查命令：
    ```bash
    ls data/ && git status --short | grep -i "data/"
    ```
  - 判定标准：`data/` 下的真实学生名单与课表**不入 git、不上服务器公网**；对外一律用脱敏「试用组织」数据（`scripts/build_trial_org.py` 生成）。发现真实数据被 `git add` = 不通过（立即移出并改 `.gitignore`）。

- [ ] **H8 · 组织内数据可见性收敛到授权组**
  - 检查命令：`python -m unittest tests.test_authz -v`
  - 判定标准：权限沿祖先链继承 + 全局角色天花板 + 多路径取 max，三条机制均有测试覆盖（docs/06 §1 四条机制）。

## 4. 隐私红线（埋点 / 日志不得含个人标识）

- [ ] **P1 · `event_log` / 埋点数据无姓名、班级、登录名**
  - 检查命令：
    ```bash
    python telemetry_report.py --assert-clean         # 对应 docs/19 CP-F
    ```
  - 判定标准：抽样 **5 行** `event_log` 记录，**不含**姓名、班级号、登录名 / 学号等可直接识别个人的字段；事件三元组（谁 / 做了什么 / 何时）中的「谁」用**匿名 id** 而非姓名。命中任何真实姓名/班级/登录名 = 不通过。

- [ ] **P2 · 埋点只采「四类原始数据」，不采内容级个人数据**
  - 检查命令：`grep -rn "INSERT.*event_log\|event_log" src/server/*.py`
  - 判定标准：埋点仅记录 人数 / 时长 / 完成率 / 满意度 四类聚合口径所需的匿名事件，**不采集**课表内容、个人具体日程文本。

- [ ] **P3 · 前端展示用 `textContent`，不拼 `innerHTML`（防注入窃取埋点）**
  - 检查命令：`grep -rn "innerHTML" web/ --include=*.js --include=*.html`
  - 判定标准：`web/` 下 **零** `innerHTML`（一律 `textContent`），阻断通过埋点/接口数据注入脚本。

## 5. 静默失效专项排查（本项目最贵的 bug 类型：不报错却给错误结果）

> 静默失效 = 「算不出 / 查不到时悄悄 `continue`，不告诉任何人」→ 系统**假阴性**（说有没冲突）。
> 假阴性比报错危险：报错用户会改，假阴性用户会**信任它**并在现场翻车。**每项必须验「修复确实落地 + 有回归断言」。**

### 5.1 闭包表清空（P0-1，已于 2026-10-04 修复，须验回归仍守住）

- [ ] **S1 · `rebuild_closure` 不再清空闭包表，且幂等、depth 语义正确**
  - 检查命令：
    ```bash
    python -m unittest discover -s tests              # 全量回归
    grep -n "rebuild_closure\|remove_edge" tests/*.py # 确认有直接调用 rebuild_closure 的回归用例
    ```
  - 判定标准（依据 docs/16 §2 实测结论）：
    - 回归用例**直接调用 `rebuild_closure()`**（不是走 `add_edge` 增量路径）；
    - **断言具体 depth 值**（3 层链 → `{3,2,1}`），**不能只数行数**（行数对、depth 错 = 更隐蔽的静默 bug）；
    - **连调多次验幂等**；`remove_edge(根组,A)` 后层级正确（`{2,1}`）。
    - 最小修法 = 2 处：`DELETE depth>1` + `frontier=[(start,0)]`。任何「只改一处」且靠行数过关的版本 = 不通过。

### 5.2 调休 `makeup` 分支（P0-2）

- [ ] **S2 · 调休日按配置周几展开，不再凭空消失**
  - 检查命令：
    ```bash
    grep -n "makeup" src/scheduler/occupancy.py
    python -m unittest discover -s tests              # 应有 makeup 展开用例
    ```
  - 判定标准：`expand_periodic` 对 `makeup` 有专门分支（按 `calendar_days.teach_dow` 查槽位，而非 `isoweekday()`）；回归用例验证「周六调休按周一课表」展开后**周六有课**。字段 `kind IN ('holiday','makeup')` 定义在、逻辑缺失 = 不通过。

### 5.3 五处「静默跳过」同源点（P0-3）

| 位置 | 触发条件 | 修后必须达到 |
|---|---|---|
| `occupancy.py:155` | 活动时段不落任何 `period_slot`（午休开会） | 返回 `UnmappedTime` 信号，上层**拒绝保存或降级告警**，不得 `{}` 静默 |
| `occupancy.py:127` | 日期不在任何 `term` 区间 | 同上，不得静默 `{}` |
| `occupancy.py:126` | 调休日 `makeup` | 见 S2 |
| `schema.sql` 视图 | `schedules` 有行但扩展表缺行 | 视图不因 INNER JOIN 静默吞孤儿行（改 LEFT JOIN 或显式告警） |
| `slots.py:150-156` | `mask_for_range` 返回 `aligned=False` | 调用方**不得丢弃** `aligned`（`_aligned` 命名 + 丢弃 = 不通过） |

- [ ] **S3 · 静默跳过统一信号落地**
  - 检查命令：
    ```bash
    grep -n "UnmappedTime\|skipped\|aligned" src/scheduler/*.py
    ```
  - 判定标准：展开结果为「有时间段但无掩码」时**必须返回标记**；`scan()` 能说出「跳过了几条、为什么」（返回 `skipped` 计数）。**任何一次 `scan()` 无法报告跳过数 = 不通过**（覆盖 docs/16 P0-3 统一修法）。

- [ ] **S4 · 位图掩码 `aligned=False` 不再被吞**
  - 检查命令：`grep -n "aligned" src/scheduler/*.py`
  - 判定标准：`mask_for_range` 的 `aligned` 返回值被**显式处理**，不是 `_aligned` 丢弃。
