# 试用问卷录入与统计口径

> 归属：纸质问卷通路（试用满意度采集）
> 口径唯一依据：docs/08-试用组织数据口径.md §4（问卷章节）
> 配套脚本：`scripts/import_survey.py` ｜ 测试：`tests/test_survey_import.py`
> 背景：队长 2026-10 定，页面内嵌打分入口**不启用**（实测收集不到有效数据），
> 满意度以**纸质问卷为主渠道**，纸质结果由队长人工转录成本文件定义的录入文件后导入。

---

## 1. 数据通路总览

```
纸质问卷（教师当场填，只印编号 T__，不印姓名）
    ↓ 队长人工转录（按本文 §2 格式）
录入文件（JSON 或 CSV，一份问卷一行/一个对象，只有编号无姓名）
    ↓ python scripts/import_survey.py import --file <文件> --db data/trial.db
survey_responses 表（脚本自建，见 §4）
    ↓ python scripts/import_survey.py report --db data/trial.db
合并报告：试用人数 / 平均使用时长 / 任务完成率 / 满意度（埋点四类，
    复用 telemetry_report 同一口径）+ 纸质问卷各题分布（本文 §6）
```

## 2. 录入文件格式（写死，只有这两种）

### 2.1 JSON（推荐，扩展名 `.json`）

```json
{
  "survey_version": 1,
  "responses": [
    {
      "trial_code": "T03",
      "q1": "yes",
      "q2": "unsure",
      "q3": 2,
      "q4": 4,
      "q5": "conflict list takes too long to load",
      "q6": "remember last selected class"
    },
    {
      "trial_code": "T07",
      "q1": "no",
      "q2": "no",
      "q3": 0,
      "q4": 2
    }
  ]
}
```

### 2.2 CSV（扩展名 `.csv`，兼容 Excel 导出，编码 utf-8-sig）

表头固定，缺一不可；一行一份问卷；含逗号/引号/换行的开放题按 CSV 标准引号转义。

```csv
trial_code,q1,q2,q3,q4,q5,q6
T03,yes,unsure,2,4,conflict list takes too long to load,remember last selected class
T07,no,no,0,2,,
```

### 2.3 字段定义与校验规则（对应 docs/08 §4.2 六题）

| 字段 | 对应纸质题目 | 类型 | 合法值 | 缺省 |
|---|---|---|---|---|
| `trial_code` | 问卷右上角编号 `T__` | 文本 | 正则 `^T\d{1,3}$`（与埋点短码同一规则） | 必填 |
| `q1` | 下周还要排一次，愿意用本系统代替现有方式吗？ | 枚举 | `yes` / `unsure` / `no`（是 / 不确定 / 否） | 必填 |
| `q2` | 会主动向同组老师推荐它吗？ | 枚举 | `yes` / `unsure` / `no` | 必填 |
| `q3` | 「一键消解」给出的方案实际采用了几个？ | 整数 | `0` / `1` / `2` / `3` | 必填 |
| `q4` | 操作是否顺畅（不需要人教就会用）几分？ | 整数 | `1`–`5` | 必填 |
| `q5` | 最想吐槽的一个功能点（开放） | 文本 | ≤ 500 字符，见 §3 隐私规则 | 可空 |
| `q6` | 最想改进的一点（开放） | 文本 | ≤ 500 字符，见 §3 隐私规则 | 可空 |
| `survey_version` | （仅 JSON 顶层）格式版本 | 整数 | `1` | 可空 |

英文枚举对照（转录时照表转换）：`是 → yes`、`不确定 → unsure`、`否 → no`。
**为什么用英文 token**：q1–q4 是结构化字段，零中文是隐私边界的一部分（见 §3），
英文 token 让「格式校验失败」与「隐私违规」两类错误互不混淆。

校验失败的行为：**整份文件一条都不入库**（先全量校验、后写库，两阶段），
错误信息逐条列出「第几份（trial_code）/ 哪一题 / 收到什么值 / 期望什么」，
绝不静默丢弃。未知字段（拼错的键）同样报错。

### 2.4 幂等规则（行为确定）

| 场景 | 行为 |
|---|---|
| 同一编号跨文件再次导入（重录修错） | **覆盖**旧记录（以最新一次导入为准） |
| 同一文件内出现重复编号 | **报错**、整份拒绝（大概率是转录笔误，如 T03/T30） |

## 3. 隐私规则（落库前强制自检）

1. **结构化字段（trial_code、q1–q4）零中文**：格式校验天然保证（枚举/整数/短码
   正则），出现中文即格式错误报错。
2. **开放题（q5、q6）允许中文**——开放题答案必然是中文，docs/08 §4.2 要求报告
   给出「开放题摘录」，全禁中文等于砍掉这两题。但开放题必须过**泄漏词表**：
   词表直接 import 自 `scripts/telemetry_report.py` 的 `LEAK_WORDS`
   （校名/年级/班级/姓名/登录名/学号等已知敏感词），**单一词表源，不另抄一份**
   （防两处漂移）。命中 → 该份该题报错、整份拒绝，错误信息指明编号与题号，
   由队长回到纸质转录环节改写脱敏后重导。
3. **每份问卷只带一个编号**：录入文件与 survey_responses 表中都不存在姓名字段，
   编号→姓名映射按 docs/08 §2 只存队长纸质记录，永不入库。
4. **词表局限（如实说明）**：词表拦的是**已知敏感词**（嘉祥/锦江/八年级/班级…），
   拦不住任意真实人名。真实人名的拦截依赖转录纪律（docs/08 §6 红线）+ 词表兜底。

> ⚠️ 口径冲突说明：本卡卡面写「录进来的内容里不得含姓名/班级名/中文可识别文本」，
> 而 docs/08 §4.2 要求报告给出开放题摘录（必然含中文）。两者无法同时满足。
> **本文执行口径**：结构化字段零中文 + 开放题中文但过泄漏词表。冲突已上报队长。

## 4. 数据库表：survey_responses

```sql
CREATE TABLE IF NOT EXISTS survey_responses (
    trial_code  TEXT PRIMARY KEY,   -- 短码 T01..T999，一份问卷一行（幂等键）
    q1          TEXT NOT NULL,      -- yes / unsure / no
    q2          TEXT NOT NULL,      -- yes / unsure / no
    q3          INTEGER NOT NULL,   -- 0..3
    q4          INTEGER NOT NULL,   -- 1..5
    q5          TEXT,               -- 开放题（可空，已过泄漏词表）
    q6          TEXT,               -- 开放题（可空，已过泄漏词表）
    imported_at TEXT NOT NULL       -- 最近一次导入时间（秒级 ISO）
);
```

**为什么是脚本自建表而不是写进 schema.sql**：schema.sql 是他人独占文件（领域层
红线），本卡不碰；表由 `import_survey.py` 的 `ensure_survey_table()` 用
`CREATE TABLE IF NOT EXISTS` 幂等创建（与 `telemetry.ensure_event_log` 同一先例：
读/写前调用，已存在的库不重建）。

**为什么不复用 event_log**（四个理由，缺一不可）：
1. event_log 的 payload 白名单（`telemetry.sanitize_payload`）只认 `{"score": 1..5}`，
   行为化答案（yes/unsure/no、0–3）与开放题根本放不进去；扩白名单要改
   `src/server/telemetry.py`——领域层只读，红线。
2. event_log 是 append-only 事件流（按 ts/session_id 组织、每事件一行）；问卷录入
   需要按 trial_code **幂等覆盖**（一问卷一行），生命周期完全不同。
3. 混入 event_log 会让 `telemetry.satisfaction()` 把同一份问卷算成多条 survey 事件，
   污染埋点满意度均值（页面内嵌辅渠道）的口径。
4. 试用四类聚合只统计 `org_kind='trial'` 的事件行，纸质问卷表若混进 event_log，
   聚合过滤条件对不上，两套数据互相干扰。

**留给队长的表结构建议**（若队长决定把该表正式收进 schema.sql 末尾追加，用上面的
DDL 即可；收编前 survey 版本数据可由 `trial_code` 主键无损迁移）。

## 5. 命令用法

```bash
# 只校验不落库（dry-run，转录后先跑一遍）
python scripts/import_survey.py check   --file surveys.json [--db data/trial.db]

# 导入（校验全过才写库）
python scripts/import_survey.py import --file surveys.json [--db data/trial.db]

# 合并报告：埋点四类 + 纸质问卷各题分布（一条命令全出）
python scripts/import_survey.py report [--db data/trial.db]
```

- `--db` 默认 `data/trial.db`（与 telemetry_report 一致）。
- 导入时对「event_log 里查无此编号」的 trial_code 打 **warning**（不阻断）：
  可能是转录笔误（T03↔T30），也可能是教师填了问卷但没触发埋点——两种都值得人工看一眼。

## 6. 统计口径（严格执行 docs/08 §4.2）

报告输出以下内容，**每题给人数分布，绝不只给均值**：

| 项 | 口径 |
|---|---|
| 回收份数 n | `COUNT(*)`（表主键即编号，天然去重） |
| q1 / q2 | yes / unsure / no 三档各几人（绝对数） |
| q3 | 0 / 1 / 2 / 3 四档各几人（绝对数） |
| q4 | n、均值、标准差（**总体标准差**，n<2 时不报标准差）、1–5 各档人数、≥4 分人数 |
| q5 / q6 | 开放题摘录（编号 + 原文，已过词表） |
| 样本量提示 | **n < 30 时不报百分比**，只报「N 人中有 M 人……」式绝对数 + 分布，并打印样本局限说明（docs/08 §4.2：计划 15 人，<30 无统计效力，主动说明比被问出来安全） |

q4 的「均值 + ≥4 占比」两个口径都算（docs/08 §1），但 n<30 时 ≥4 以**人数**呈现
（占比仅供内部参考、不进对外材料）。

满意度主渠道 = 纸质问卷（本文件）；页面内嵌 survey 事件为辅渠道，仍由
`telemetry_report` 原样打印，能力不退化。

## 7. 与现有工具的关系

| 文件 | 关系 |
|---|---|
| `scripts/telemetry_report.py` | **不修改**。本脚本 import 其 `report()`（四类聚合，单一口径源）与 `LEAK_WORDS`（泄漏词表，单一词表源），在自己的 `report` 子命令里合并输出 |
| `src/server/telemetry.py` | 只读调用，不改 |
| `web/` | 不动（页面内嵌打分入口已被队长否决） |
| `docs/08 §4` | 唯一问卷口径依据；本文只是它的「录入工具化」落地 |
