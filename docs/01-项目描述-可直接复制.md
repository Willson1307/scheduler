## 3. 简介 · 完整版（约 180 字，用于 README / 项目书）

```
中学的课表（长期重复事务）和活动（一次性事务）通常各管各的：排课时看不见已安排的活动，
于是撞车；出了冲突又只能靠人反复试。本项目把两者归一化到同一套底层模型——
「某个对象在某天的哪些节次被占用」——用位运算做统一的冲突检测，再让自建的约束求解器
做自动排布与一键消解：硬约束（教师、教室、班级撞课，教室容量）保证百分之百满足；
软约束（连堂、单日课时上限、主科不排末节等）以代价形式参与权衡，其权重由本校公开的
往期课表统计学习得到（w = −ln(1−p)，p 为历史满足率）。全部计算在本地完成，
不调用任何大模型接口，断网也能运行。
```

## 5. 技术要点（三条，答辩时讲这三条就够）

```
一、对象图（DAG + 闭包表）：一个学生可以同时属于班级和社团；
    「可被调度的对象」与「可登录的账号」是正交的两层，学生一定在对象图里，
    但不一定需要账号。

二、统一占用模型：周期日程和一次性活动都展开成「(日期, 当天槽位掩码)」，
    冲突检测就是一次按位与——排课因此看得见已安排的活动，不会撞车。

三、自建约束求解器：回溯搜索 + 前向检查 + MRV 启发式；硬约束必满足、
    软约束按代价权衡。求解环节不调用任何大模型，大模型只在入口负责听懂人话。
```
