## 3. 简介 · 完整版（约 230 字，用于 README / 项目书）

```
中学的课表（长期重复事务）和活动（一次性事务）通常各管各的：排课时看不见已安排的活动，
于是撞车；出了冲突又只能靠人反复试。本项目把两者归一化到同一套底层模型——
「某个对象在某天的哪些节次被占用」——用位运算做统一的冲突检测，再让自建的约束求解器
做自动排布与一键消解：硬约束（教师、教室、班级撞课，教室容量）保证百分之百满足；
软约束（连堂、单日课时上限、主科不排末节等）以代价形式参与权衡，其权重由本校公开的
往期课表统计学习得到（w = −ln(1−p)，p 为历史满足率）。

权限上，「可被调度的对象」与「可登录的账号」是正交的两层：谁能在哪个组里看什么、改什么，
由沿组织树继承的四档授权（查看/编辑/管理/拥有）决定；学生一定在对象图里，但不一定需要账号。

自然语言入口采用五层降级架构：本地规则解析器（覆盖 70–80%，零 API、断网可用）是绝对主力，
云端大模型仅在本地层无法解析时作为可选增强，且失败会自动静默回落。
全部计算在本地完成，断网也能运行。
```

## 5. 技术要点（答辩讲这四条）

```
一、对象图（DAG + 闭包表）：一个学生可以同时属于班级和社团；
    「可被调度的对象」与「可登录的账号」是正交的两层，学生一定在对象图里，
    但不一定需要账号——正好匹配本校学生不持有终端的现状。

二、统一占用模型：周期日程和一次性活动都展开成「(日期, 当天槽位掩码)」，
    冲突检测就是一次按位与——排课因此看得见已安排的活动，不会撞车。

三、自建约束求解器：回溯搜索 + 前向检查 + MRV 启发式；硬约束必满足、
    软约束按代价权衡。求解环节不调用任何大模型，大模型只在入口负责听懂人话。

四、按组的四档授权：查看 / 编辑 / 管理 / 拥有，沿对象图祖先链继承，
    多条路径取最高档；刻意不做「负权限」（多父结构下语义不自洽）。
```

## 7. 一句话回答"你的 AI 是训练的还是调接口"

```
都不是。我们自建约束求解器做搜索与优化——约束满足本身就是人工智能的经典分支；
软约束的权重是从本校公开的往期课表里统计学习出来的。

求解环节完全不调用大模型：冲突检测、一键消解、结果解释都在本地完成。
自然语言入口有一个五层降级架构——本地规则解析器（覆盖 70–80%，零 API、断网可用）
是绝对主力，云端大模型只在本地层解析不了时才用，且失败会自动静默回落，
断网时功能完全不受影响。发给外部模型的内容只有用户指令文本本身，
不含任何课表、班级名或姓名。
```

> 这段是**最容易被追问**的地方，务必讲清三层：
> ① 求解是自研 ② 权重是学习出来的 ③ 云端只做入口理解且可降级。

## 8. 已知限制（诚实写进项目书，比被评委当场问出来强）

```
一、暂不支持调课补课（数据模型已定义，功能未实现）。
二、跨天活动需拆成两条一次性日程，且必须属于同一组。
三、非整节（如 14:15–15:00）的安排支持有限，按连续区间处理。
```

## 9. 项目书里可以强调的"工程实现"硬素材

```
· 口令存储：PBKDF2 十万轮 + 随机盐 + 常数时间比较
· 零第三方依赖 = 零供应链攻击面；全部参数化查询，零注入面
· Bearer token（非 Cookie）= 天然免疫 CSRF
· 1500 名学生只有对象行、没有账号行 = 数据库泄露也拿不到可登录凭据
· SQLite 启用 WAL，读写不互斥
· 登录失败限流、请求超时与并发上限、目录不列、前端禁用 innerHTML
```
