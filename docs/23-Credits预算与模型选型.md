## 3. 模型选型矩阵

| 场景 | 推荐 | 理由 |
|---|---|---|
| **默认（不折腾）** | **WorkBuddy Auto 模式** | 框架按机型自动路由，最省心 |
| **主线构建** B0–B4、F1–F3b | **GLM-4.6**（云端） | 200K 上下文，装得下 AGENTS.md + docs/19 + 契约；价格约 Kimi K2.7-Code 的 28% |
| **卡壳 / 难题** | **DeepSeek V4-Pro**（云端） | 贵但强，只在卡住超过 30 分钟时升级 |
| **零散小活** L8/L10/L11/L12/L13 | **本地 Ollama `qwen2.5-coder:3b`** | 零成本；单文件、不读大量项目文档 |
| **批量 / 格式化** | 本地 3b | 同上 |
| 断网兜底 | 本地 3b | 必须可用 |

### 🔴 为什么主线不能用本地 3b

主线卡要求 AI 先读三份文档：`AGENTS.md`（约 310 行）+ `docs/19`（约 250 行）+ `docs/07-API契约.md`（300 行以上）。
**3b 模型的上下文装不下这么多**，会读了后面忘前面、漏掉红线约束。
这不是"慢一点"的问题，是**会出错**。

### 判据（别凭感觉选模型）

**可用本地 3b** —— 同时满足：
- 单文件产出
- 不需要读懂别人的代码
- 没有写死的约束（签名、红线）
- 做错了重跑代价低

**必须上云端** —— 满足任意一条：
- 要改现有代码
- 有硬约束（如 `handle(...)` 签名不许改、禁改 `routes.py`）
- 错了会污染 main 分支
- 需要一次成型

## 4. 省 Credits 的硬规则（不降模型档位）

> 原则：**省在流程上，不省在模型上。** 用弱模型做难卡 = 返工 = 更贵。

| # | 规则 | 省多少 |
|---|---|---|
| 1 | **一张卡做完就开新对话** | ⭐最大。上下文累积是长程任务第一杀手 |
| 2 | 禁止为确认签名重读 `src/scheduler/`（用 docs/19 附录 A） | 大 |
| 3 | 单卡只碰自己的独占文件，不探索范围外 | 中 |
| 4 | 先写针对性测试，再改代码 | 中 |
| 5 | 测试用 `:memory:` + `port=0`，不起真服务 | 中 |
| 6 | 前端一次成型（先想清楚再写，别反复微调视觉） | 中 |
| 7 | 重试上限 2 次（github push、跑测试都一样） | 小 |
| 8 | 长卡拆成「先出设计稿 → 确认 → 再实现」两轮 | 中 |
