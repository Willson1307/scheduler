## 0. 选型第一判据：错误形态，不是价格

| 错误形态 | 典型表现 | 后果 | 档位决策 |
|---|---|---|---|
| 🔴 **静默** | 测试全绿但逻辑错；越权能读数据却不报错；掩码错一位 | 几天后暴露，可能已进 main | **不降档** |
| 🟢 **报错** | 语法错、接口 404、引用写错、样式错位 | 当场发现，改两句 | **降到最低档** |

**按此判据分类本项目的工作**：

| 静默高危（不降档） | 报错型（可降到底） |
|---|---|
| 安全实现（鉴权 / 越权 / 组织过滤 / 限流） | 文档、材料、答辩文案 |
| 领域层改动（`occupancy.py` / `m2.py` / 位运算） | 注释、命名、格式整理 |
| 判据类代码（测试断言、校验链） | 展板配图、README |
| 权限档位语义（`min(max, ceiling)` 这类） | 纯样式调整 |
| 数据迁移 / 重建脚本 | |

> ⚠️ **不要用「卡号」判断**（B2 是安全卡、B3 不是）——这是 v2.x 的做法，已被证伪。
> B4 原本是「消解功能卡」，2026-10-06 查出 `api_resolve.py` 有同源 IDOR 后**变成鉴权卡**。
> **判据永远是：这张卡实际要写什么代码。**

### 1.1 🔥 DeepSeek-V4.1-Flash-1017（2026-10-17 发布）

| 项 | 值 |

**9 项里赢 7 项，价格是 GLM-5.3 的 1/6。**

#### ⚠️ 三条必须知道的坑

1. **全部厂商自报，无独立验证**。且 **Terminal-Bench 跑在 Claude Code 框架、DeepSWE 跑在 Mini-SWE-V2** →
   这些是「模型 + 脚手架」的分数，换 harness 会变。
2. **工程完成度仍有代差**。第三方实测（302.AI）结论：「视觉和创意已经够打，**工程完成度仍有代差**」；
   另一实测做赛车游戏 20 分 39 秒交付但 A/D 转向符号写反（GPT-6 Astra 10 分钟一次成型）。
3. **「输出更短」这个省钱机制对我们作用有限**。本项目以**读上下文**（`AGENTS.md`+`docs/`+代码）为主，
   输入 token 占主导，而**输入单价没降**。真实节省来自倍率差（0.11x vs 0.69x），不是「输出更短」。

#### 🔴 它不能替代 GLM-5.3 的全部理由

**1017 没有任何安全类 benchmark**（无 CyberGym / SEC-Bench / ExploitBench）。
「通用编码强」≠「写出的鉴权不留 IDOR」——后者是 `docs/23 §3.3` 特意区分的另一种能力。
→ **安全核心实现仍由 GLM-5.3 承担，这条不因 1017 便宜而改变。**

### 3.1 特殊模型定位（限时 / 待验证）

| 模型 | 定位 | 红线 |
|---|---|---|
| **Space Bunny**（0.08x，$0 预览限时） | 辅助、写脚手架、格式整理、文档起草 | ❌ **禁碰安全实现代码**；⛔ 不能写进排期依赖 |
| **Step-5-Preview**（0.00x，独家限免） | 大批文档交叉核对 | ⛔ 限免会到期（推测约 10/29），**按会到期做预案** |
| **Hy3**（0.05x，限时免费） | 简单 / 模板化任务 | ⛔ 免费期结束时间未知，预算按 0.05x 计 |
| **MiMo-V2.6-Pro**（0.13x） | 仅安全审计（有 CyberGym/SEC-Bench 证据） | 上线仅 3 周，通用编码已被 1017 反超 |
| **DeepSeek-V4.1-Flash-1017**（0.11x） | 通用编码 / Agent / 接口 / 领域层 / 前端 | **无安全 benchmark**，不进安全链路 |

**为什么禁碰安全实现**：安全代码会被组委会核查来源。弱模型写出的安全代码一旦有漏洞，
评委第一问就是「这段是谁写的」——**说不清就是致命伤**。
这与「安全实现与审查分离」是同一条铁律的两个侧面。

### 3.2 🔴 五条选型铁律

1. **静默高危工作不降档**（安全实现、领域层改动、判据类代码）。
   禁用 Space Bunny 与本地 3b 写安全实现。
2. **判据看「实际写什么代码」，不看卡号**——B4 曾是功能卡、后查出 IDOR 变鉴权卡。
3. **安全实现与安全审计用不同模型**——一个要精确、一个要想象力；同源审查等于自审。
4. **免费 / 限免 / 夜间折扣模型不得进关键路径**——标签会变，写进排期 = 到时候没得用。
5. **一张卡不要中途换模型**——上下文与代码风格漂移，比换档省下的钱更贵。
   **所有云模型仅作开发助手**，不接产品自然语言入口；产品须断网可跑，与模型选型无关。

### 3.3 ⚠️ 「安全实现」与「安全审计」不是同一件事

| | 安全实现 | 安全审计 |
|---|---|---|
| 做什么 | 写出**没有**越权/IDOR 的鉴权代码 | 在已有代码里**找出**越权/IDOR |
| 最难的地方 | 规格落地的**精确性**（少一个 `org_id` 过滤就漏） | 攻击面**想象力**（想到别人想不到的路径） |
| 评测对应 | 真实项目漏洞检出记录 + 代码正确性 | CyberGym / SEC-Bench / Cyber Index |
| 本项目用 | **GLM-5.3** | **MiMo-V2.6-Pro** |

🔴 **所以 CP-H 审查用 MiMo，写鉴权用 GLM-5.3，两者不冲突。**

### 3.4 边界：MiMo 与 1017 各管一段

| 模型 | 管什么 | 不管什么 |
|---|---|---|
| **MiMo-V2.6-Pro**（0.13x） | 安全**审计**：有 CyberGym 94.0 / SEC-Bench 66.3 / Cyber Index 开源第一 | 通用编码已被 1017 反超（DeepSWE 71.9 vs 77.0）且更贵（0.13x vs 0.11x）→ **日常编码不再用它** |
| **DeepSeek-V4.1-Flash-1017**（0.11x） | 通用编码 / Agent / 接口 / 领域层 / 前端 | **无任何安全 benchmark** → 不能用于安全审计或安全实现 |

→ **两者不重叠，按上表分工，不要互相替代。**

## 4. 省 Credits 的硬规则（不降档位的省法）

> 原则：**先省流程，再考虑换档；换档按 §0 判据走，不按价格走。**

| # | 规则 | 省多少 |
|---|---|---|
| 1 | **一张卡做完就开新对话** | ⭐最大。上下文累积是长程任务第一杀手 |
| 2 | **报错型工作直接给最低档**（文档 / 材料 / 注释 → Hy3） | 大 |
| 3 | 单卡只碰自己的独占文件，不探索范围外 | 中 |
| 4 | 先写针对性测试，再改代码 | 中 |
| 5 | 测试用 `:memory:` + `port=0`，不起真服务 | 中 |
| 6 | 长卡拆成「先出设计稿 → 确认 → 再实现」 | 中 |
| 7 | **不赶时间的活挪到夜间**（Hy4 夜间免费、V4-Pro/V4.1-Flash 有夜间折扣） | 中 |
| 8 | **别在同一分钟死磕**：隔 2–5 分钟再试（push、跑测试都一样） | 小 |

## 5. 超支判据与降级

| 触发条件 | 动作 |
|---|---|
| 单卡用掉预算 **150%** 仍未完成 | 停下来报告，**不许硬撑** |
| 积分告急 | **先砍卡**（减范围）；**不许动静默高危工作的档位** |
| 报错型卡预算告急 | 可无脑降到底档（Hy3 / V4.1-Flash） |

> 🔴 **宁可砍卡（减范围），不可降档（增返工）。**
> 🔴 **静默高危工作不在降级范围内**——降级顺序里它们永远不动。
> 🔴 判据仍是「这张卡实际写什么代码」（§3.2 铁律 2），不是卡号。

### 5.5 遇 6004 / 429 限频的处置

> **前提变化（2026-10-25）**：升级标准版后 GLM-5.3 **已基本不再限频**。
> 本节保留作兜底，触发概率已大幅下降。

**症状**：`错误码 6004｜当前使用的模型服务在一段时间内的请求次数或 token 用量达到了上限`，附重置时间戳。
> **这不是积分耗尽，是该档位自身的限频窗口。** 别报「额度不够」。

#### ⛔ 三条铁律

| # | 规则 | 理由 |
|---|---|---|
| 1 | **⛔ 绝不切本地 `qwen2.5:3b` 顶主线** | 3b 编码弱 + 上下文装不下 `AGENTS.md` + `docs/23` → **漏红线约束** |
| 2 | **⛔ 静默高危工作不降档** | 鉴权代码组委会要核查来源，降档写出的漏洞说不清 |
| 3 | **✅ 换模型必须告知队长** | 降档是排期决策，不得自行默默换（§3.2 铁律 1） |

#### ✅ 正确处置顺序

1. **先按 §0 判断这张卡是静默高危还是报错型**：
   - **报错型** → 直接降到最低可用档（Hy3 / V4.1-Flash），**不等窗口**
   - **静默高危（安全实现）** → GLM-5.3 固定在档，**等窗口，不换模型**（§7 已取消替代验证）
2. **别空等窗口**：等窗口期间去做无依赖的卡（文档类、审查类）
3. **窗口过了自动恢复**，安全卡换回 GLM-5.3
4. **报错别在同一分钟反复重试**（§4 第 8 条）
