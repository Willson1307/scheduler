# 客户端更新与数据同步

> 日期：2026-09-25 ｜ 起因：队长提问「后续更新时的客户端推送等迭代相关功能考虑了吗？」
> **结论：MVP 不做实时推送，但有两件事现在必须留好口子，否则后期补的代价极高。**

---

## 1. 先拆清楚：所谓「更新」其实是三件不同的事

| # | 场景 | 本质 | 不做会怎样 |
|---|---|---|---|
| **a** | 我们发了新版前端，老师浏览器还在跑旧 JS | **静态资源缓存** | 现场最惨的一种：改了 bug 但页面表现没变，还以为没修好 |
| **b** | 管理员改了课表，教师页面看不到 | **数据变更同步** | 教师按旧课表行动；演示时两个人看到的不一致 |
| **c** | 现场断网 | **离线降级** | 章程硬要求「断网也能跑」，这一条是**必做**不是可选 |

三件事的解法完全不同，混在一起讨论会选错技术。

---

## 2. 技术约束（先摆清楚，别选错）

- **Python 标准库 + SQLite，零第三方依赖** → 标准库**没有 WebSocket 服务端**。
  自实现 RFC 6455（握手 + 帧掩码 + 分片 + 心跳）约 200–300 行，易错，且现场断网演示时反而更脆弱。
- HTTP 层是 `http.server` + `ThreadingHTTPServer`。
- **前端原生 JS，无构建步骤，零 https 外链**。

---

## 3. 选型对比

| 方案 | 依赖 | 实现量 | 断网表现 | 结论 |
|---|---|---|---|---|
| **轮询**（定时 `GET /api/version`） | 0 | ~15 行 | 失败即静默降级，显示「最后更新于 xx:xx」 | ✅ **MVP 采用** |
| **SSE**（`text/event-stream`，生成器 yield） | 0（标准库可做） | ~40 行 | 断线自动重连，同样可降级 | ✅ **二期可选，提升观感** |
| **长轮询** | 0 | ~30 行 | 同轮询 | 备选 |
| **自实现 WebSocket** | 0 但自写协议 | 200–300 行 | 握手失败处理复杂 | ❌ 成本高、现场风险大 |
| **Service Worker / PWA** | 0（纯前端） | 中 | 缓存静态资源，离线可用 | ⚠️ MVP 不做；若现场环境不稳再考虑 |

**为什么轮询就够**：MVP 是「单人操作 + 多人只读查看」——学生只读、教师 150 人、试用 15 人，
真正的并发写冲突极少。10 秒一次轮询，冲突检测的结果延迟 10 秒没人感知得到。
**实时协同编辑（多人同时拖课表 + 加锁）不在 MVP 范围，也不应该进。**

---

## 4. 🔴 现在就要留的两个口子（后补成本极高）

### 4.1 数据版本号 `data_revision`（schema 层，现在加零成本）

```sql
-- 追加到 schema.sql 末尾（属 Ryan 的独占范围）
CREATE TABLE IF NOT EXISTS data_revision (
    org_id TEXT PRIMARY KEY,
    rev    INTEGER NOT NULL DEFAULT 0
);
```

- 所有**写操作**（创建/修改/删除日程、应用消解方案）成功后：`UPDATE data_revision SET rev = rev + 1 WHERE org_id = ?`
- 客户端 `GET /api/version` 拿到 `rev`，与本地比对；不一致才拉全量。
- 后续若升级到 SSE，推送的也只是 `rev` 变化这个信号，**上层逻辑完全不用改**。

> **为什么现在必须加**：`rev + 1` 要散落在所有写路径里。等 API 全写完再补，
> 要回头改十几个文件且极易漏掉某条路径（漏掉的那条就是「改了但页面不刷新」的玄学 bug）。
> 现在加是一张表 + 一行 UPDATE。

### 4.2 静态资源版本号（前端约定，写进 AGENTS.md）

- 所有资源引用带版本：`app.js?v=20261008`（或文件名带 hash）。
- `static.py` 响应头加 `Cache-Control: no-cache` + `ETag`。
- 版本号由 `config.py` 统一导出，改一处即可。

> 这一条**现在不定，10/20 现场改样式就会踩**：老师浏览器缓存着一周前的 JS。

---

## 5. 轮询的具体约定（若采用）

- 间隔 **10 秒**；页面不可见（`document.hidden`）时**暂停**，可见时立即拉一次。
- 只在**页面停留超过 30 秒**后才开始轮询（避免一打开就刷）。
- 断网/失败：不弹红字报错，只在角落显示灰色「最后更新于 20:31 · 离线」。
- 轮询**只拿 `rev`**，不拿全量数据；`rev` 变了才拉一次全量 → 流量可忽略。

---

## 6. 明确不做（写下来，避免中途加需求）

- ❌ WebSocket / 实时协同编辑 / 操作锁
- ❌ 多端推送通知（离校后的消息推送需要外部服务，必然破「零依赖 + 断网可跑」）
- ❌ 移动端 App（学生不持有终端，是学校场景硬约束）
- ❌ Service Worker（MVP；现场环境确认后再评估）
