# 05 · 部署与运维（F6：S15 部署就绪包 + S16 文档）

> 分支 `feat/deploy`｜前置 B4（✅ 已在 `main`）｜验收：删 `data/` → 一条命令 → 30 秒内 `/api/health` 200 且页面可打开。

## 0. 三条硬线（先读再动手）

1. **演示口径**：演示库 3 班 ×10 生 → **23 处原始冲突 / 3 个冲突组**。这个数字已写进 README 与报名材料，截图、演示、配图一律用 23。
2. **演示日期**：必须固定 `--today 2026-09-08`。不带会落到「今天」所在周，只扫到 1 处冲突**且不报错**（docs/17 §1 事故）。
3. **数据红线**：`data/` 的库含真实名单，**不得出校、不得上公网**；对外一律用脱敏试用库（账号口令见 `scripts/build_trial_org.py` 的 `ADMIN_LOGIN` / `ADMIN_PASSWORD`），10/18 试用结束即关停。

## 1. 一条命令冷启动（验收命令）

```bash
python deploy/start.py
```

预期输出：

```
INFO 冷启动命令：python scripts/run_server.py --host 127.0.0.1 --port 8000 --today 2026-09-08
INFO 库缺失时自动初始化（3 班 ×10 生 / 9 师 / 4 室 + 周末槽位）
READY host=127.0.0.1 port=8000 db=.../data/demo.db today=2026-09-08
INFO 已初始化新库：seed 规模 3 班 ×10 生 / 9 师 / 4 室，term_start 锚定 2026-09-08 所在周周一
INFO 页面 http://127.0.0.1:8000/ ｜ 健康检查 http://127.0.0.1:8000/api/health ｜ Ctrl-C 退出
```

| 判据 | 达标方式 |
|---|---|
| 删 `data/` 后一条命令能起 | 库缺失时服务端 `ensure_database()` 自动 seed，无任何预备步骤 |
| 30 秒内 `/api/health` 200 | 实测远小于 30s：seed 48 个对象是进程内纯 Python，无网络往返 |
| 页面可打开 | `GET /` → 200 `text/html`（`web/index.html` + `app.js` 全本地，零外链） |
| 无需联网 | 零第三方依赖、无 CDN、只 bind 本机 + 读写本地 SQLite |

登录账号 `admin`，口令见 `src/scheduler/seeds.py:38`（与 `scripts/smoke.py:65` 同一口径）。

参数：

| 参数 | 说明 |
|---|---|
| `--port N` / `--port 0` | 固定 / 随机端口（Windows 下端口占用不报错，被占时优先用随机端口） |
| `--host 0.0.0.0` | 校园网内可达；🔴 必须同时限制安全组只放行校园网段（§5） |
| `--today YYYY-MM-DD` | 演示日期注入，默认 `2026-09-08` |
| `--db PATH` | 换库，如 `--db data/trial.db` 连试用库 |
| `--open` | 就绪后自动打开浏览器 |
| `--no-seed` | 库不存在也不初始化（连已有库） |

## 2. 验收脚本（一条命令自证）

```bash
python deploy/acceptance.py           # 完整验收：备份 → 删 data/ → 跑一条命令 → 30 秒校验 → 恢复
python deploy/acceptance.py --keep-data   # 不删 data/（试用期验证用，不碰现场数据）
```

校验项：

1. `data/` 已清空；
2. **30 秒内** `/api/health` 200 且 `ok=true`（硬上限，超时即 FAIL）；
3. `GET /` 200 且 `text/html`、`GET /app.js` 200（页面真能打开，不只是 health 活着）；
4. 防「假绿」：`POST /api/login` 拿得到 token、`/api/conflicts` 是 23/3、`POST /api/resolve` 23 → 0。

> 第 4 项不是加戏：docs/17 §7 的事故里 health / doctor / demo_cli **全绿**，但 `main` 上 `/api/resolve` 是 404。**只验 health 会漏掉「接口不在这个分支上」。**

数据安全：删 `data/` 前先把需保留的文件（如试用库、`scrub.salt`）复制到临时备份目录，确认成功后才删，验收结束再恢复；备份失败即中止，绝不先删后想。演示库 `demo.db` 属可再生产物，不在备份范围。

## 3. 部署步骤

### 3.1 Windows 开发机（现场演示）

1. 切到 `feat/deploy` 分支并 `git pull`；
2. 安装 Python ≥ 3.10（**不装任何第三方包**，`requirements.txt` 全注释）；
3. `python deploy/start.py --open`；
4. 浏览器打开 `http://127.0.0.1:8000/`，登录 `admin`；
5. 断网复核：关 Wi-Fi → 刷新页面 → 功能照常（docs/17 §3.2 断网环节）。

### 3.2 Linux 服务器（校内 / 试用）

1. 部署到 `/opt/scheduler`（属主 `scheduler:scheduler`，`data/` 需可写）；
2. `python3 --version` ≥ 3.10；无 pip 依赖；
3. `python3 deploy/start.py --host 0.0.0.0 --port 8000`；
4. 防火墙 / 安全组只放行校园网段（§5）；
5. 常驻用 systemd（§4）；一次性验证用 `tmux` / `nohup`。

## 4. systemd unit（纸面交付）

```ini
# /etc/systemd/system/scheduler.service
[Unit]
Description=课表活动调度辅助系统（本地运行，断网可用）
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/scheduler
Environment=SCHEDULER_HOST=0.0.0.0
Environment=SCHEDULER_TODAY=2026-09-08
# 与人工演示同一条命令：避免「服务器上跑的」和「现场跑的」不是同一套
ExecStart=/usr/bin/python3 /opt/scheduler/deploy/start.py --host 0.0.0.0 --port 8000
Restart=on-failure
RestartSec=3
NoNewPrivileges=yes
PrivateTmp=yes

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now scheduler
sudo systemctl status scheduler
journalctl -u scheduler -f      # 看日志，READY 行在这里
```

`start.py` 在 POSIX 下会把 SIGTERM 转发给子进程，systemd 停机不会留下孤儿服务。若路径不在 `/opt/scheduler`，改 `WorkingDirectory` 与 `ExecStart` 两处即可。

## 5. 防火墙 / 安全组（🔴 只放行校园网 IP 段）

**默认不需要开口子**：`start.py` 默认只绑 `127.0.0.1`，仅本机可访问。现场演示就用这个，最安全。

只有需要从校园网访问时才绑 `0.0.0.0`，**且必须**只放行校园网：

**云安全组（入方向）**

| 协议/端口 | 源 | 说明 |
|---|---|---|
| TCP 8000 | `<校园网 IPv4 段/掩码>` | 🔴 真实网段待队长提供，**严禁对 `0.0.0.0/0` 开放** |

**firewalld**

```bash
sudo firewall-cmd --permanent --new-zone=scheduler-campus
sudo firewall-cmd --permanent --zone=scheduler-campus --add-source=<校园网IP段/掩码>
sudo firewall-cmd --permanent --zone=scheduler-campus --add-port=8000/tcp
sudo firewall-cmd --reload
```

**ufw**

```bash
sudo ufw allow from <校园网IP段/掩码> to any port 8000 proto tcp
```

**Windows 防火墙（管理员 PowerShell）**

```powershell
New-NetFirewallRule -DisplayName "scheduler (校园网)" -Direction Inbound `
  -Protocol TCP -LocalPort 8000 -RemoteAddress <校园网IP段/掩码> -Action Allow
```

> 红线：`data/` 的库含真实名单，**不得出校、不得上公网**。确需上公网前，必须换脱敏试用库并过一遍 `docs/21-安全基线检查清单.md`。

## 6. 运维

| 场景 | 操作 |
|---|---|
| 看日志 | 前台跑看 stdout；systemd 用 `journalctl -u scheduler -f` |
| 重启 | Ctrl-C 后重跑；`systemctl restart scheduler` |
| 端口被占 | `python deploy/start.py --port 8001` 或 `--port 0` |
| 重置演示库 | `python scripts/reset_demo.py`（回到 48 对象 / 23 冲突） |
| 重建试用库 | `python scripts/build_trial_org.py`（脱敏假名 + `scrub.salt`） |
| 演示「今天」 | 固定 `--today 2026-09-08`，输出逐字可复现 |
| 体检 / 端到端自检 | `python scripts/doctor.py`｜`python scripts/smoke.py` |
| 停机 | Ctrl-C / `systemctl stop scheduler`；试用结束即关停 |

**已知限制（如实，不夸大）**：

- 登录 token 只存内存，服务重启即失效，需重新登录（`auth.py` 进程级密钥）；
- 单进程 `ThreadingHTTPServer`，够演示与试用；不做多机、负载均衡、数据迁移（docs/02 边界）；
- 无数据库迁移机制，schema 变更 = 删 `data/` 重建（演示库本就是可再生产物）。

## 7. 故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| 页面只显示 1 处冲突 | 没带 `--today`，落到了第 5 周 | 固定 `--today 2026-09-08` |
| 启动被拦「端口已被占用」 | 已有实例在跑 | `--port 8001` 或 `--port 0`；Windows 下 `netstat -ano \| findstr 8000` 确认真凶 |
| 页面 404 且返回 JSON「静态资源目录不存在」 | `web/` 缺失或 `--web` 指错 | 确认仓库根有 `web/index.html` |
| health 绿但「一键消解」404 | 服务端代码不在当前分支（docs/17 §7 事故） | `git branch --show-current`，并直接打一次 `/api/resolve` |
| 登录后刷新要重新登录 | 设计如此（token 仅存内存 + 重启失效） | 重新登录 |
| `data/` 写入失败 | 目录不可写 | 检查属主 / 权限 |
| 演示连到了试用数据 | 库选错 | `--db data/trial.db` + 试用账号 |
