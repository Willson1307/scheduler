# 基础框架边界：什么先做，什么先别碰

> 队长提醒"不要往太深的地方动工，先搭基础框架"——这份文件把深浅边界写死，
> 避免做着做着又钻进算法细节里。

---

## 一、原则：先广度，后深度

**现在要的是一条能从头跑到尾的细线**（启动 → 打开页面 → 看到冲突 → 点一下消解），
不是某个环节做得多深。每一层先做到"能通"，深度留到闭环跑通之后再补。

---

## 二、分层与深浅边界

| 层 | 属于"基础框架"（现在做） | 属于"深水区"（先别碰） |
|---|---|---|
| **领域层** | ✅ 已完成（B0 数据层、B4 约束引擎 + M2） | M1 全局排课、M3 局部补排、偏好权重学习（**均已从「砍掉」改为「可选恢复」，主线闭环后再做**） |
| **服务层** | HTTP 入口、路由骨架、健康检查、JSON 出入参、设计意图注释 | 审计日志、并发与事务优化 |
| **会话/权限** | ✅ **按组四档（查看/编辑/管理/拥有）+ 沿闭包继承为本轮主线**（S5/S5b，见 `AGENTS.md` §9） | 正式 Session 持久化、密码找回、终端扫码登录 |
| **前端** | 一个单页：课表周视图 + 冲突列表 + "一键消解"按钮 | 拖拽排课、多标签页、组织树可视化编辑器 |
| **数据** | 种子数据（试用组织）能跑通 | CSV 批量导入 1500 人、往期课表导入 |
| **部署** | 一条命令启动，断网可跑 | Docker、多机部署、数据迁移脚本 |

---

## 三、技术栈决定：**标准库，零第三方依赖**

用 Python 标准库的 `http.server` 搭服务，**不引入 FastAPI**。

理由：

1. **现场必须断网可跑**——依赖越少，现场翻车概率越低；
2. 演示机不一定能装包（机房/借用电脑）；
3. 后端逻辑全部写成与框架无关的**纯函数**，将来真要换 FastAPI，
   只需要替换一层薄薄的适配代码，领域层一行不用改。

代价：路由要手写，代码比 FastAPI 啰嗦一点。这个代价换"现场稳"，值得。

## 四、目录结构（骨架）

> ⚠️ 本节是 **9/24 的早期草图**，只为讲清分层思路。
> **实际目录与文件归属以 `AGENTS.md` §4（文件所有权）为准** —— 后续已新增

```
│   ├── demo.py           命令行演示
│   └── run_server.py     一键启动
└── tests/
```

## 五、"基础框架完成"的验收点

一条端到端能跑通：

```
python scripts/run_server.py --init-demo
# 浏览器打开 http://127.0.0.1:8000
# 1) 用 admin 登录
# 2) 看到本周冲突列表
# 3) 点"一键消解" → 冲突数下降 → 刷新后真的变了
```

跑通这条线，基础框架就算完成。之后再往任何一层加深，都有地方放。
