## 0. 状态标签约定

本文件里每个功能都带一个标签，**标签就是它的真实状态**：

| 标签 | 含义 | 能否在答辩时说"已实现" |
|---|---|---|
| ✅ **已做** | 代码在 `main` 上，且有测试 | ✅ 可以 |
| 🟡 **在做** | 已开工但未合 `main` | ⚠️ 只能说"在做" |
| ⬜ **候选** | 只有设计，**代码不存在** | 🔴 **绝对不能说已实现** |
| ❌ **已砍** | 决定不做，但保留设计 | 🔴 不能说已实现，但可以说"我们考虑过并决定不做" |

> **教训**：本项目曾发生过把"已定位未修"写成"已修"的情况。评委核查源代码时，
> 一句话对不上，全盘信任就没了。**标签必须诚实。**

## 3. 候选详述

### 3.1 B8 审批流（提议 → 批准 → 落库）⭐ 最有价值，但时间不够

**这是什么**：班级终端不能直接改课表，只能"提议"；教务处批准后才落库。

**为什么想做**：这是**永久差异化壁垒**。市面上的排课软件都是"要么能改要么不能改"，
我们是**四档权限 + 强制审批流**：
- `pending` 状态不改动任何数据
- 越权操作返 **403**
- 批准时若已撞车返 **409 + 冲突对象名**

**技术设计**（尚未实现）：
```
change_requests(id, org_id, group_id, requester_id, payload, status, reviewer_id, created_at)
  status ∈ (pending / approved / rejected)
  payload = 提议的日程变更（before/after 对比）
```

**流程**：
1. 班级终端 POST 提议 → `status=pending`，🔴 **不改任何课表数据**
2. 教务处（`approve` 档）查看待审列表
3. 批准 → **服务端重新跑冲突检测**；撞车则返 **409 + 冲突对象名**，不落库
4. 通过则落库，`status=approved`
5. 全程记审计日志

**为什么现在不做**：
- 10/23 前要把「网页 → 周视图 → 冲突列表 → 一键消解」跑通，这是**主线**
- 审批流需要 3-4 天（表+ 接口 + 前端待审列表 + 审计）
- 🔴 **和主线抢时间不划算**

**答辩怎么处理**：可以说"权限模型已经支持四档，审批流是它的自然延伸"——
**架构上确实已经为它留好了接口**（`propose` 档和`approve` 档都已实现），
但**不要说"已实现审批流"**。

### 3.2 B5 自然语言入口

**这是什么**：用户输入"帮我把周三上午的物理挪开"，系统理解成结构化约束。

####🔴 AI 三层分工（这是本项目的核心设计决策，必须说清）

| 步骤 | 做什么 | 用大模型吗 |
|---|---|---|
| ① **理解需求** | 自然语言 → 结构化约束 | ✅ **该用**（大模型强项） |
| ② **搜索计算** | 约束空间里算出可行方案 | 🔴 **不该用**（这是求解器的活） |
| ③ **解释与微调** | 方案说成人话、按偏好排序 | ✅ **该用**（但要过校验） |

**"求解不调 AI"的准确含义：只禁第 ② 步**，不是全部禁。详见 `docs/04`。

#### 🔴 机制：AI 提议 → 求解器校验 → 才展示

```
用户自然语言
    ↓
大模型① 理解 → 结构化约束 {动作, 日期范围, 目标对象, 期望}
    ↓
🔴 交给自建求解器② 搜索（不含大模型）
    ↓
大模型③ 解释 → 人话+ 代价 + 理由
    ↓
🔴 求解器校验：不满足硬约束 → 驳回，不展示
    ↓
展示给用户
```

**这个机制的价值**：**大模型永远不能直接改数据**。它只能提议，
必须过求解器这一关。这既是安全性，也是答辩的加分点——
"AI 参与但不被信任"是一个有分量的设计判断。

#### 技术选型（已调研）

| 方案 | 状态 | 备注 |
|---|---|---|
| 智谱 GLM-4-Flash | 🔴 已排除 | 未成年人注册限制 |
| 本地 Ollama `qwen2.5:3b` | ✅ 主通道 | 免费、断网可用、7b 队友独显 |
| DeepSeek / Groq / Cerebras | ⏸ 备选 | 云端通道 |

**为什么优先本地**：项目红线是**断网可跑**。云端 LLM 一断网就用不了，
本地模型没有这个问题。

**为什么还没做**：意图解析模块（`intent.py`）**尚未编码**（已设计，未实现）。
而且这是个"锦上添花"项——自然语言只是**输入方式**，
核心能力（冲突检测 + 一键消解）**已经能用**。

---

### 3.3 B9 临时微调 / 多方案选择（S21）

**这是什么**：消解时给用户 2-3 个方案（代价不同），让用户挑而非直接应用最优。

**技术基础**：🔴 **已经有了**。`api_resolve.py` 的 GET 版本已经实现 top-3 方案预览
（`m2.top_plans(plans, n=3)`），每项带 `cost` / `diff_text` / `impact` / `moves` / `warnings`。

**所以B9 缺的是**：前端的多方案对比 UI（并排显示、标出代价差异）。

**为什么延后**：后端已经能出多方案，前端展示是纯 UI 工作。可以现场演示时口头说明
"后端已经支持多方案，现在演示的是自动选最优"，**不算说谎**。

---

### 3.4 F5 埋点与试用数据采集 🔶 **必做**（合规项）

**为什么必做**：章程硬要求**真实用户体验数据**。没有埋点就没有数据。

**只采四类数据**（🔴 隐私红线）：
1. 操作事件（哪个功能被用了几次）
2. 耗时（从打开到完成消解的时长）
3. 任务完成率（是否成功消解）
4. 满意度（试用后的问卷评分）

**🔴 绝对不采**：
- ❌ 姓名 ❌ 班级 ❌ 登录名
- 🔴 任何可关联学籍的字段
- 🔴 真实学生名单与课表（**不得出校、不得上公网**）

**技术方案**：本地埋点 → 试用结束后导出聚合统计（**只导出汇总，不导出行级**）。

**合规做法**：用**脱敏的"试用组织"**（虚构名称），🔴 真实数据不出校。

### 3.5 S18 档位

**这是什么**：算力档位切换（本地小模型 / 云端大模型）。

**为什么不砍会后悔**：它其实是**"AI 含量"的证据**之一。

**但现在砍的理由**：档位切换是"锦上添花"，而同一目标（AI 含量证明）可以用
**偏好权重学习**更好地达成——那是**真的在学东西**，比"能切模型"更有说服力。

## 4. 优先级建议：如果 10/23 前只来得及做一项

### 🔶 答案：F5 埋点（不是 F5 之外的任何项）

**理由**：

| 选项 | 为什么不是它 |
|---|---|
| B8 审批流 | 3-4 天，做不完；且会挤掉主线 |
| B5 自然语言 | 2 天，且需要先写意图解析；但自然语言只是输入方式，核心能力已有 |
| 拖拽排课 | 纯 UI，收益主要在"展示"，而展示分只有 20% |
| 读时上卷 | 性能优化，**评委现场跑不出来**（除非专门测） |
| 🔶 **F5 埋点** | 🔴 **没有它，现场答不出"真实体验数据"这一项**——这是章程硬要求 |

**一句话**：F5 不做，**参赛资格有问题**；其他不做，只是少几个加分点。

## 5. 已砍清单及原因

| 功能 | 决策 | 原因 |
|---|---|---|
| **M1 全新排课** | ❌ 砍 | 🔴 5 天+、风险最高。队长早就定了"**先打通端到端细线**"（见 `docs/02`）。**排课不是本次的核心价值，消解才是。** |
| **S18 档位** | ❌ 砍 | 锦上添花；AI 含量的证明用权重学习更扎实 |
| **拖拽排课** | ⏸ 延后 | 展示分只占 20%，且有"一键消解"这个更亮的交互 |
| **读时上卷** | ⏸ 延后 | 降48 倍是真的，但**现场跑不出来**（除非专门压测） |
| **M3 局部补排** | ⏸ 延后 | 优先级低于 M2，M2 是 CP-D 生死线 |
| **偏好权重学习** | ⏸ 延后 | 🔴 **很可惜**——它是"AI 含量"最硬的证据（从往期课表学权重 `w = -ln(1-p)`）。但需要历史课表数据，🟡 取决于能否拿到往期课表 |
| **学生个人账号** | ❌ 砍 | 绕开"初始密码怎么发到学生手上"这一无合法路径的问题（见项目记忆） |
| **食堂错峰/ 传感器计数等** | ❌ 早期作废 | 2026-09-24 队长确认整体作废（六模型交叉评审后） |

### 关于"偏好权重学习"——🔴 一个值得在答辩时主动提的点

它是本项目**最贴合"AI"叙事**的设计：
> 从本校往期课表里学出偏好权重 `w = -ln(1-p)`（p = 该偏好被满足的历史比例），
> 再把权重喂给**自建求解器**。这是真的"从数据里学"，而不是调API。

**但它现在没做**。答辩时**可以说"我们设计了这条路径"**，🔴 **不能说"我们已经能学权重"**。
